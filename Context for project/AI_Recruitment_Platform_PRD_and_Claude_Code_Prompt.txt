AI-POWERED GLOBAL
RECRUITMENT PLATFORM
Product Concept, System Architecture and Claude Code Development Prompt

Core principle: Describe yourself. Describe your needs. Let AI find the right match.

Global market  |  All professional sectors  |  Candidate and Employer portals

 Document purpose
This document defines the product concept, three-module architecture, key user journeys, privacy approach, matching logic and a master development prompt for building an interactive hackathon MVP using Claude Code. It is intended to be shared with project colleagues and used as a common implementation brief.
1. Product vision
Build an AI-powered, two-sided recruitment platform that helps people find suitable work and helps employers and recruitment organizations identify qualified candidates quickly. The platform converts unstructured candidate information and vacancy descriptions into structured data, then compares them through an explainable matching engine.
The initial product scope is global and covers all industries and professional sectors. The platform should support multiple languages, currencies, salary periods, employment types and country-specific qualification requirements through a configurable architecture.
The product is not simply a job board. Its core value is structured information, AI-assisted profile and vacancy creation, and two-sided matching.

2. Three-module system architecture
 
The two portals are separate user experiences connected to one shared data layer and matching engine. Candidate and vacancy information is normalized before matching. Results are returned to the relevant portal subject to privacy and access permissions.
2.1 Module A: Job Seeker Portal
Purpose: allow individuals to create a structured professional profile with minimal effort and discover suitable vacancies.
Registration and account management
•	Register and log in using email and password, with secure account management.
•	Create, edit and maintain a professional profile.
•	Manage profile visibility and consent settings.
•	Request account deletion and deletion of personal data, subject to applicable legal retention requirements.
Three profile creation methods
1. AI Guided Profile Creation
The user enters a profession, such as “electrician”. The AI asks profession-specific questions about qualification level, safety permits, experience, installation types, education and countries where the person is authorized to work. The questionnaire must adapt to the occupation.
2. CV Upload
The user uploads a PDF or DOCX file. The system extracts work experience, education, skills, languages, certificates and licenses. It creates a structured draft, identifies missing or ambiguous information, and asks follow-up questions. The candidate reviews and approves the profile before it is saved.
3. Natural Language Input
The user describes their background in ordinary language. Example: “I am a truck driver with seven years of experience, C and CE driving categories, Latvian and English language skills, and availability from December in Riga or within 50 km.” AI converts this into structured fields and asks relevant follow-up questions.
Candidate profile data
•	Personal information and professional title.
•	Industry, occupation and standardized skills.
•	Professional experience, education and qualifications.
•	Certificates, licenses and other supporting documents.
•	Languages and proficiency levels.
•	Current location, preferred regions and mobility.
•	Employment type preferences and availability date.
•	Expected salary, currency and payment period.
•	CV and supporting documents.
•	Profile visibility and consent preferences.
Candidate dashboard
•	Profile completion status.
•	Number of potentially matching vacancies.
•	Recommended vacancies with Match Scores and score explanations.
•	Employer information, salary range, location and distance where available.
•	Application and communication status.
•	Filters for location, industry, salary, employment type and availability.
2.2 Module B: Employer / Recruiter Portal
Support recruitment agencies, direct employers and government or public-sector organizations. The organization profile should include organization name, type, industry, location, description and contact information.
Three vacancy creation methods
1. AI Guided Vacancy Creation
The employer enters a role, such as “electrician”. AI asks about mandatory qualifications, safety permits, experience, technical skills, location, salary, start date and number of employees required.
2. Job Description Upload
The employer uploads an existing PDF or DOCX job description. AI extracts and structures the requirements.
3. Natural Language Vacancy Creation
Example: “We need three experienced electricians in Riga. Candidates must hold the required electrical safety qualification, have at least three years of experience and be available from December. Salary is EUR 1,500 to EUR 2,000 per month.” AI converts the description into structured vacancy fields.
Vacancy data
•	Job title, industry and occupation.
•	Required skills, mandatory qualifications and preferred qualifications.
•	Minimum experience and other relevant experience criteria.
•	Location, geographical search radius and work arrangement.
•	Employment type and working schedule.
•	Salary range, currency and payment frequency.
•	Required start date, opening date and application deadline.
•	Number of employees required.
•	Additional conditions and eligibility requirements.
Employer dashboard
•	Active vacancies and recruitment status.
•	Number of potentially matching candidates.
•	Ranked candidate profiles with Match Scores and explanations.
•	Candidate qualifications, experience and availability.
•	Salary expectations and geographical distribution.
•	Contact permissions and candidate interest status.
•	Recruitment pipeline and analytics.
Salary optimization
Allow an employer to adjust the offered salary range and recalculate the potentially matching candidate pool. For example, show how the candidate pool changes when the monthly salary changes from EUR 1,000 to EUR 1,500 or EUR 2,000. Support hourly, monthly and annual compensation. The dashboard must distinguish real candidate counts from simulated demo data.
2.3 Module C: AI Matching Engine and Central Database
This is the central intelligence layer. It receives structured candidate profiles and vacancy requirements, normalizes data, validates mandatory criteria, calculates compatibility and returns explainable results to both portals.
Data normalization
•	Normalize job titles and occupation terminology.
•	Map skills to a consistent skills catalogue and recognize equivalent terms across languages.
•	Normalize qualifications, certifications and experience levels.
•	Normalize locations, currencies, salary periods and availability dates.
•	Preserve source information and mark extracted or AI-inferred fields as unverified until confirmed.
Matching parameters
Parameter	Comparison	Treatment
Skills	Candidate skills against vacancy skills	Weighted compatibility
Qualifications	Education, certificates and licenses	Mandatory or preferred
Experience	Relevant years and type of experience	Weighted compatibility
Location	Candidate location and work location	Distance / mobility rules
Availability	Candidate start date and vacancy start date	Date compatibility
Salary	Expected salary and offered range	Range compatibility
Employment type	Candidate preference and vacancy type	Compatibility
Other requirements	Additional role-specific conditions	Explicitly configured
Generate an overall Match Score from 0 to 100 and show a breakdown of the factors contributing to the score. Mandatory requirements must be treated separately from preferred requirements. A candidate who does not meet an essential qualification must not receive a high score merely because other criteria are strong. The system must not present AI assumptions as verified facts.
Two-sided matching
•	Candidate view: “Based on your profile, we found 24 potentially suitable vacancies.”
•	Employer view: “Based on your vacancy requirements, we found 86 potentially suitable candidates.”
These figures are illustrative demo values, not claims about real market availability.
Central database entities
•	Users and authentication records.
•	Candidate profiles and professional experience.
•	Employer organizations and organization members.
•	Job vacancies and vacancy requirements.
•	Skills, qualifications, education and certifications.
•	Candidate availability and salary preferences.
•	Matching results and score explanations.
•	Applications, communication records and consent records.
•	Analytics events and recruitment history.
3. Privacy, security and trust
Candidate profile visibility must be configurable. The recommended default is Anonymous.
•	Private: the profile is not discoverable by employers.
•	Anonymous: employers can see professional qualifications, skills, experience and matching information, but not the candidate’s name or direct contact details.
•	Public: the candidate can make selected professional information visible under their chosen permissions.
Contact details must not be disclosed without explicit candidate consent. Implement role-based access control, secure authentication, appropriate protection of uploaded documents, and account deletion workflows. For a global product, plan for applicable data protection and employment rules in each operating jurisdiction. Do not imply that a demo implementation is legally compliant without a separate legal and security review.
4. Analytics and market intelligence
Candidate analytics
•	Number of matching vacancies.
•	Salary distribution for matching roles.
•	Demand for the candidate’s skills.
•	Regional employment opportunities.
•	Profile competitiveness and improvement suggestions.
Employer analytics
•	Available candidate pool.
•	Candidate distribution by region.
•	Candidate salary expectations.
•	Supply and demand for specific skills.
•	Number of candidates meeting mandatory criteria.
•	Recruitment pipeline and estimated time to fill a vacancy.
Analytics must be calculated from platform data. Where data is simulated for the hackathon demo, label it clearly as simulated.
5. UI / UX requirements
•	Professional, modern SaaS interface with responsive desktop and mobile layouts.
•	Separate navigation and dashboards for Candidate and Employer portals.
•	Consistent design system across the platform.
•	Clear onboarding and low-friction profile and vacancy creation.
•	Conversational AI interfaces for guided questionnaires.
•	Readable matching explanations and data visualizations.
•	Landing page with two primary entry points: “Find a Job” and “Hire Talent”.
•	Visual representation of the central AI engine connecting both sides.
6. Recommended technical implementation
•	Frontend: React or Next.js with TypeScript.
•	UI: Tailwind CSS and a modern component library.
•	Backend: Next.js API routes or a dedicated backend service.
•	Database: PostgreSQL.
•	ORM: Prisma or an equivalent.
•	AI integration: configurable LLM API integration.
•	Authentication: secure authentication with role-based access.
•	Document processing: PDF and DOCX text extraction.
•	Matching: deterministic, explainable rules-based scoring combined with AI-assisted semantic analysis.
If an AI API key is unavailable, provide a simulated AI service so the full demo remains functional. Seed the database with realistic fictional candidates, employers and vacancies across several sectors. Keep AI provider integration modular so a real provider can be connected later.

9. Success criteria for the hackathon demo
•	A user can complete a candidate profile using at least one AI-assisted path.
•	An employer can create a structured vacancy using an AI-assisted path.
•	Both records are saved in the same central database.
•	The matching engine returns ranked results with understandable score explanations.
•	Mandatory criteria affect eligibility or ranking as configured.
•	Changing salary or location changes the matching results where relevant.
•	Anonymous candidate data remains protected until consent is granted.
•	The main scenarios can be demonstrated without external API dependencies.

Appendix B. Assumptions and items requiring later validation
•	The global scope is a product ambition. Country-specific employment law, data protection, salary conventions and qualification recognition require jurisdiction-specific implementation.
•	The initial matching score is a product design concept. Weightings and eligibility rules must be tested with real recruiters and candidates.
•	Employer reliability scores should not be launched until there is a transparent, verifiable methodology and appropriate safeguards against manipulation.
•	Candidate verification and security-clearance checks require lawful data sources, consent and country-specific procedures.
•	Any market size, candidate count, salary benchmark or recruitment-time estimate shown in a demo must be labelled as simulated unless supported by actual data.
